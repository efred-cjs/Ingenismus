INGENISMUS GUÍA DE INSTALACIÓN Y PUESTA EN MARCHA Visualización de
mediciones de dos sensores MPU6050 con Firebase Realtime Database

Versión de la guía: 2 de noviembre de 2026 Proyecto: Web_ingenismus

============================================================ 0. OBJETIVO
Y ARQUITECTURA GENERAL
============================================================

Esta guía reúne el flujo de trabajo que construimos para Ingenismus: una
página web en HTML y CSS que consulta Firebase Realtime Database
mediante JavaScript y representa las mediciones de dos sensores MPU6050
usando Chart.js.

Arquitectura:

ESP32 + sensores MPU6050 (o simulador Python) | v Servidor Flask en
Python (puerto 5000) | v Firebase Admin SDK | v Firebase Realtime
Database /mediciones | v Firebase Web SDK (JavaScript en el navegador) |
v Chart.js | v Panel Ingenismus

Funciones de cada componente:

1.  ESP32 o simulador: Produce mediciones de los sensores. En las
    pruebas se utilizó un simulador Python para generar datos ficticios
    de sensor_id 1 y 2.

2.  Servidor Flask: Recibe las mediciones mediante HTTP POST en
    /mediciones, valida los campos y las guarda en Firebase.

3.  Firebase Realtime Database: Almacena las lecturas bajo la ruta
    /mediciones.

4.  Página web: Consulta directamente Firebase. No necesita que Flask ni
    el simulador estén encendidos para consultar lecturas que ya fueron
    guardadas.

5.  Chart.js: Dibuja las gráficas del acelerómetro y del giroscopio.

IMPORTANTE SOBRE EL PROYECTO: Las mediciones de los sensores describen
movimiento y orientación. Por sí solas no diagnostican TEA ni deben
presentarse como diagnóstico. En el contexto del proyecto, sirven para
registrar y analizar patrones de movimiento bajo un protocolo definido y
supervisión adecuada.

La configuración web contiene valores como: - apiKey - authDomain -
databaseURL - projectId - storageBucket - messagingSenderId - appId

La configuración web se utiliza en ingenismus.js. No debe confundirse
con el archivo de cuenta de servicio de Firebase Admin.

La apiKey de una aplicación Firebase web no equivale a una contraseña de
administrador. Aun así, se deben aplicar reglas de seguridad y
restricciones apropiadas.

============================================================ 6. REGLAS
DE FIREBASE UTILIZADAS EN LAS PRUEBAS
============================================================

Reglas que se publicaron para permitir que el navegador leyera las
mediciones durante las pruebas:

{ “rules”: { “mediciones”: { “.read”: true, “.write”: false, “.indexOn”:
[“fecha_servidor”] } } }

Significado:

-   .read: true permite lectura pública en la ruta mediciones.
-   .write: false impide que clientes web escriban en esa ruta.
-   .indexOn crea un índice para fecha_servidor y ayuda a consultas
    ordenadas por ese campo.

IMPORTANTE: Estas reglas fueron utilizadas para pruebas con datos
ficticios. No son recomendables para producción, porque cualquier
persona que conozca la URL de la base puede leer las mediciones.

Para producción se debe implementar Firebase Authentication y reglas de
autorización que restrinjan el acceso por usuario, rol, institución o
participante, según el diseño del sistema. Una regla sencilla como
“.read”: “auth != null” solo exige iniciar sesión, pero no separa los
datos por participante.

Firebase Admin SDK en el servidor Python utiliza credenciales
administrativas y puede escribir aunque la regla .write sea false para
clientes normales. Las reglas de Admin SDK no funcionan igual que las
del SDK web.

/* ===================================== CONSULTAR FIREBASE
===================================== */

function consultarLecturas() {

    if (cancelarLectura) {
        cancelarLectura();
        cancelarLectura = null;
    }

    estadoConexion.textContent = "Conectando...";

    // ref recibe el objeto database y la ruta interna.
    const ruta = ref(database, RUTA_LECTURAS);

    const consulta = query(
        ruta,
        orderByChild("fecha_servidor"),
        limitToLast(LIMITE_LECTURAS)
    );

    cancelarLectura = onValue(
        consulta,

        (snapshot) => {

            lecturas = [];

            snapshot.forEach((registro) => {
                const dato = registro.val();
                lecturas.push(dato);
            });

            lecturas.sort(
                (a, b) =>
                    Number(a.fecha_servidor) -
                    Number(b.fecha_servidor)
            );

            estadoConexion.textContent = "Conectado";

            actualizarGraficas();
        },

        (error) => {

            console.error("================================");
            console.error("ERROR DE FIREBASE");
            console.error("Código:", error.code);
            console.error("Mensaje:", error.message);
            console.error("================================");

            estadoConexion.textContent = "Error: " + error.code;
        }
    );

}

/* ===================================== ACTUALIZAR GRÁFICAS Y
ESTADÍSTICAS ===================================== */

function actualizarGraficas() {

    const sensorSeleccionado = Number(sensorSelect.value);

    const datosSensor = lecturas.filter(
        dato => Number(dato.sensor_id) === sensorSeleccionado
    );

    const etiquetas = [];
    const aceleracion = [[], [], []];
    const giroscopio = [[], [], []];

    datosSensor.forEach((dato) => {

        const fecha = new Date(Number(dato.fecha_servidor));

        etiquetas.push(fecha.toLocaleTimeString());

        aceleracion[0].push(dato.aceleracion_x ?? null);
        aceleracion[1].push(dato.aceleracion_y ?? null);
        aceleracion[2].push(dato.aceleracion_z ?? null);

        giroscopio[0].push(dato.giroscopio_x ?? null);
        giroscopio[1].push(dato.giroscopio_y ?? null);
        giroscopio[2].push(dato.giroscopio_z ?? null);
    });

    // Actualizar acelerómetro.
    graficaAcelerometro.data.labels = etiquetas;
    graficaAcelerometro.data.datasets[0].data = aceleracion[0];
    graficaAcelerometro.data.datasets[1].data = aceleracion[1];
    graficaAcelerometro.data.datasets[2].data = aceleracion[2];

    graficaAcelerometro.options.plugins.title.text =
        `Acelerómetro - Sensor ${sensorSeleccionado}`;

    graficaAcelerometro.update();

    // Actualizar giroscopio.
    graficaGiroscopio.data.labels = etiquetas;
    graficaGiroscopio.data.datasets[0].data = giroscopio[0];
    graficaGiroscopio.data.datasets[1].data = giroscopio[1];
    graficaGiroscopio.data.datasets[2].data = giroscopio[2];

    graficaGiroscopio.options.plugins.title.text =
        `Giroscopio - Sensor ${sensorSeleccionado}`;

    graficaGiroscopio.update();

    // Actualizar estadísticas.
    totalLecturas.textContent = datosSensor.length;

    if (datosSensor.length > 0) {

        const ultima = datosSensor[datosSensor.length - 1];

        ultimaLectura.textContent =
            new Date(Number(ultima.fecha_servidor)).toLocaleTimeString();

    } else {
        ultimaLectura.textContent = "Sin datos";
    }

}

/* ===================================== EVENTOS
===================================== */

btnConsultar.addEventListener(“click”, consultarLecturas);

sensorSelect.addEventListener(“change”, actualizarGraficas);

/* ===================================== INICIALIZACIÓN
===================================== */

from pathlib import Path from flask import Flask, request, jsonify
import firebase_admin from firebase_admin import credentials, db

FIREBASE_DATABASE_URL =

import json import random import time from datetime import datetime from
urllib.request import Request, urlopen from urllib.error import
HTTPError, URLError

API_URL = “http://127.0.0.1:5000/mediciones” INTERVALO_SEGUNDOS = 1.0

def crear_medicion(sensor_id):

    return {
        "sensor_id": sensor_id,

        "aceleracion_x": random.randint(-2000, 2000),
        "aceleracion_y": random.randint(-2000, 2000),
        "aceleracion_z": random.randint(14000, 17500),

        "giroscopio_x": random.randint(-250, 250),
        "giroscopio_y": random.randint(-250, 250),
        "giroscopio_z": random.randint(-250, 250)
    }

def enviar_medicion(datos):

    cuerpo = json.dumps(datos).encode("utf-8")

    solicitud = Request(
        API_URL,
        data=cuerpo,
        headers={"Content-Type": "application/json"},
        method="POST"
    )

    with urlopen(solicitud, timeout=5) as respuesta:
        mensaje = respuesta.read().decode("utf-8")
        return respuesta.status, mensaje

def main():

    print("===================================")
    print(" SIMULADOR WIFI - ESP32 + MPU6050")
    print("===================================")
    print(f"API: {API_URL}")
    print("Generando datos FICTICIOS...")
    print("Presiona Ctrl+C para detener.")

    contador = 0

    try:

        while True:

            inicio = time.time()

            for sensor_id in (1, 2):

                datos = crear_medicion(sensor_id)

                try:

                    codigo, respuesta = enviar_medicion(datos)
                    contador += 1

                    hora = datetime.now().strftime("%H:%M:%S")

                    print(
                        f"[{hora}] Sensor {sensor_id} | "
                        f"HTTP {codigo} | Datos: {datos} | "
                        f"Respuesta: {respuesta}"
                    )

                except HTTPError as error:

                    detalle = error.read().decode(
                        "utf-8",
                        errors="replace"
                    )

                    print(f"Error HTTP {error.code}: {detalle}")

                except (URLError, TimeoutError) as error:

                    print(f"No se pudo conectar con la API: {error}")

            transcurrido = time.time() - inicio

            time.sleep(
                max(0, INTERVALO_SEGUNDOS - transcurrido)
            )

    except KeyboardInterrupt:

        print("\nSimulación detenida.")
        print(f"Mediciones enviadas correctamente: {contador}")

if name == “main”: main()

============================================================ 13.
ENTENDER LOS INDICADORES Y LA CONEXIÓN
============================================================

La página web se conecta directamente a Firebase mediante el SDK web de
Firebase.

El servidor Flask no es el intermediario de lectura de la página. Flask
recibe y guarda las mediciones; el navegador consulta Firebase
directamente.

Por tanto:

-   Si se detiene el simulador, dejan de generarse datos ficticios.
-   Si se detiene Flask, dejan de recibirse nuevas mediciones por ese
    servidor.
-   Si ambos se detienen, las mediciones anteriores siguen guardadas en
    Firebase.
-   La página puede seguir consultando las mediciones almacenadas,
    siempre que Firebase esté disponible y las reglas permitan la
    lectura.
-   El indicador Conectado de la página indica que la consulta/escucha
    de Firebase pudo establecerse; NO indica que Flask o los sensores
    estén activos.

La función onValue() mantiene una escucha en tiempo real sobre la
consulta de Firebase. Cuando se agregan registros, el navegador recibe
una actualización y vuelve a dibujar las gráficas.

El botón Actualizar datos vuelve a registrar la escucha; el selector
cambia el sensor mostrado sin tener que consultar de nuevo Firebase.

============================================================ 15. MEJORAS
PENDIENTES Y RECOMENDACIONES
============================================================

1.  Comparación simultánea: Mostrar los dos sensores al mismo tiempo, en
    lugar de seleccionar uno solo.

2.  Estadísticas: Calcular promedio, mínimo, máximo, rango y
    variabilidad de cada eje.

3.  Sesiones: Identificar cada sesión de medición y asociar lecturas con
    una sesión, no solamente con una marca de tiempo.

4.  Historial: Permitir consultar sesiones y rangos de fechas
    anteriores.

5.  Indicadores independientes: Separar estado de Firebase, estado del
    servidor Flask y recepción reciente de datos de los sensores. El
    indicador actual solo informa sobre Firebase.

6.  Autenticación: Implementar Firebase Authentication antes de
    compartir el sistema con usuarios reales.

7.  Reglas de producción: No conservar “.read”: true en producción.
    Restringir la lectura por usuario, rol, institución o participante.
    Evitar que un usuario autenticado pueda leer indiscriminadamente
    todos los registros.

8.  Seguridad de credenciales: Mantener serviceAccountKey.json
    exclusivamente en el servidor. No subirlo al repositorio ni
    incluirlo en la página web.

9.  Validación: Validar rangos, tipos, identificadores, frecuencia y
    estructura de las mediciones en el servidor.

10. Protección de datos: Si se trabaja con participantes, definir
    consentimiento, minimización, anonimización o seudonimización,
    controles de acceso, retención y eliminación de datos conforme a las
    obligaciones aplicables.

11. Interpretación: Las señales de acelerómetro y giroscopio permiten
    estudiar movimiento; no constituyen por sí mismas una prueba ni
    diagnóstico de TEA.
